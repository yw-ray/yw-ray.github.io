1. How are layers grouped and cores allocated?

Read each column top to bottom in exported segment order. Each row is one execution group; colored bars show the number of cores assigned to each layer out of 64. Bar width is core allocation, NOT execution time. Layers sharing a group may overlap subject to dependencies; this is not a measured timeline.

2. Selected layer: core placement details

Which data slice runs on which core?

Each chiplet contains a physical 2 × 2 core grid. Cells show the selected layer's B/C/H/W partition indices (zero-based), not tensor element indices. Amber = the selected layer's assignment differs at this physical core. Gray = another layer or idle. Chiplet positions remain fixed.

3. How does this layer's routed traffic change?

Arrows show this layer node's D2D routed bytes divided by its scheduling batch, summed across 8 channels. Includes traffic routed to/from DRAM. These are byte volumes per batch item, not required bandwidth. Both maps share one color scale.

4. Which links change, and does final bandwidth change too?

Sorted by this layer's absolute traffic change. Final bandwidth is the whole workload's accepted profile (B/cycle, summed across 8 channels); other layers may determine it. A before/after comparison does not isolate the cause when several mapping choices change together.
