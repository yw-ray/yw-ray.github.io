Bandwidth reduction — reflection allowed

Baseline definitions and reduction calculation

Baseline 1 — Uniform four-port tile (K=1): Every manufactured chiplet includes north, east, south and west TX/RX capacity, including unused outer ports.

Baseline 2 — Uniform A/H/I tiles (K=3): Corner A tiles have two ports, edge H tiles three, and interior I tiles four. All present TX/RX channels have the same uniform bandwidth.

What do K1 and K3 mean? K is the number of reusable tile templates, not the number of chiplets or cores. K1 (K = 1) uses one four-port template everywhere. K3 (K = 3) provides three position-specific templates: corner (A, two ports), edge (H, three ports), and interior (I, four ports). Only templates needed by the mesh are instantiated: a 2 × 2 mesh uses only corner tiles. Rotations and allowed reflections reuse a template; they do not add templates. Baseline 2 and the proposed design both use this three-template scheme; the proposed design sizes TX/RX directions independently.

Proposed — Asymmetric A/H/I tiles: Each tile's TX/RX directions are sized independently in allocation quanta, with legal tile rotations. Capacity is counted over every manufactured tile instance. Every selected workload must meet its own reference execution time.

Let N be chiplet count, P channels per directional port, and u the smallest feasible uniform bandwidth per channel on the same eligible mapping pool and time limits. For a jointly supported group, u is the maximum of its workloads' minimum feasible uniform settings. Workloads run separately on the shared hardware; their traffic is not summed.

Capacity(Baseline 1) = N × 4 × 2 × P × u
Capacity(Baseline 2) = (2N_A + 3N_H + 4N_I) × 2 × P × u
C_proposed = Σ_tiles Σ_present_ports Σ_channels (TX capacity + RX capacity)
Absolute reduction = C_baseline − C_proposed [B/cycle]
Reduction (%) = 100 × (C_baseline − C_proposed) / C_baseline

Choose Baseline 1 or Baseline 2 as the reference for every chart, and percentage or absolute reduction as the metric. The CSV includes Baseline 1, Baseline 2 and proposed capacities. Absolute reduction measures provisioned bandwidth, not the number of physical links removed. Baseline 2 is the minimum feasible uniform setting, not the separate full 256 B/cycle reference.

Example, archived CNN: Baseline 1 = 36,864; Baseline 2 = 27,648; proposed = 24,960 B/cycle. Baseline 2 reduction = 2,688 B/cycle = 9.7%; Baseline 1 reduction = 11,904 B/cycle = 32.3%.

What does “cores per chiplet” mean?

A chiplet is a compute die containing one or more accelerator cores. A core is the simulator's PolarCore compute-and-buffer block. Each core contains multiple processing elements (PEs); each PE contains multiple MACs. A MAC is a multiply–accumulate resource.

Green blocks mark SRAM: each core owns a 2 MiB unified buffer (UL3). The enlarged core shows this SRAM separately from the PE array. Its drawn position indicates ownership, not physical placement on silicon. Local activation, weight and output buffers are modeled in addition to UL3.

One core = 4 × 4 PEs × 8 lanes/PE × 4 MACs/lane = 512 main MACs. The actual input selects mm=0 (PolarCore), mac_dim=512 and ul3=2048 KiB. Here mac_dim=512 selects the MAC scale; it is not a 512 × 512 array. The source also models 32 separate LR arithmetic units; these are not included in the 512 main-MAC count. Its area model uses 8-bit main-MAC and separate FP16 LR cost assumptions.

The mapper aligns input channels C to vecSize=4 and output channels K to laneNum=8. The 4 × 4 PE-level bus dimensions can distribute other loop dimensions depending on the mapping. This diagram shows the modeled resource hierarchy, not a fixed systolic dataflow or physical floorplan. Workload utilization and measured latency still depend on partitioning, memory and communication.

Total cores = chiplet count × cores/chiplet
Total main MACs = total cores × 512
Physical core mesh = (chiplet mesh rows × core_side) × (chiplet mesh columns × core_side)

For example, 16×16, 64×4 and 256×1 each contain 256 cores and 131,072 main MACs. Their chiplet meshes are 4×4, 8×8 and 16×16, respectively, while each has a 16×16 physical core mesh. Chiplet boundaries and D2D traffic differ. The chart's mesh label refers to the chiplet mesh, not the PE array. A/H/I denote reusable port templates; their count does not specify the number of compute cores.

Communication within a chiplet uses the on-die NoC; transfers crossing chiplet boundaries use D2D ports. A port channel is a communication resource, not a compute core. The buffer totals above sum separate per-core UL3 capacities; they do not represent one shared SRAM bank.
