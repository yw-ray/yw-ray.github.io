Traffic demand between chiplets

Source → destination bytes per workload and batch, before routing. Each row is a sender, each column a receiver. Self traffic is excluded. Native replay of the oracle-best mapping on each HW. Updated 2026-10-20 13:22.

What sets this matrix

  • Workload and batch. Which layer consumes which tensor, tensor sizes, skip connections, and how much traffic is DRAM traffic.
  • Spatial mapping. How layers are grouped and pipelined, how each layer is partitioned (batch, spatial, channel), and which chiplet runs each partition and which DRAM holds its data.
  • Not the links or the routing. Link widths and the route (XY, direction-steered, bandwidth-weighted) change the path only. A multicast counts once per receiving chiplet, so path-based forwarding does not add rows.
  • Uniform and asymmetric HW differ only because each HW gets its own fastest mapping.

Cells show percent (blank below 0.5%). Node ids: chiplets 0..N−1 (q = column × rows + row, row 0 at the top), D0..D3 = DRAM controllers. "Ring next" is the next chiplet in the ring layer-pipelining order. Parity: replay cycles equal the oracle cycles of the picked mapping on that HW.
